# Fix the Trainer signal before the prompts

**Run two cheap checks first, then a search-score fix and a potential. Together they test Evan's signal-versus-architecture question for under 3 GPU-hours.** The most likely signal gap is upstream of the prompts. The main-phase search score for "play Trainer X" uses the pilot's own prompt answers (code fact, env/agents.js, read 2026-10-24), and probe C68 X1 found those answers no better than random. So the search target probably teaches "a Trainer is worth a blank card", whatever the pilot answers later. Nothing here measures that bias yet, so check it before building. After the checks, the best-supported signals are ones that change only the advantage, the value target or a potential. Those need no oracle answers and sit outside Evan's row 60. Signals that train the policy on search-chosen prompt answers get the row-60 mark. Costs below are estimates from code size, not measurements. The only measured numbers are the ones you gave: X1 +0.002 +/- 0.009 over 6,080 games per variant, lambda 1 within a turn -37 Elo, never-fading prize shaping -31 Elo, and the loop's keep bar of about 1 sd (pooled sd 0.0115).

Not recommended: RND or curiosity (novelty is not credit, and shuffles break forward-prediction curiosity; [Burda 2018](https://arxiv.org/abs/1808.04355)), self-imitation (it uses the same blind V; [Oh 2018](https://arxiv.org/abs/1806.05635)), and Align-RUDDER (it needs demonstrations). The Suphx-style learned turn potential comes only after probe 1b is positive (Suphx's predictor was trained on human logs, so only the human-free version, trained on self-play results, is allowed; [Suphx](https://arxiv.org/html/2003.13590v2)). Already queued in ar/ideas.md and not repeated here: prompt-row loss weight, turn-level lambda, prompt-row entropy, per-type advantage normalisation, value-only first iteration, prompt-heavy practice.

## What can the 5-minute loop even see

The keep bar is about 1 sd (0.0115), and X1 shows the pilot's prompt answers move the result by only 0.002 +/- 0.009. Any prompt-level signal therefore starts with a ceiling the loop may be unable to resolve. Use the ceiling probe C73-x1b before spending screens on #7 or #8. Items 3, 4, 8 and 9 are pure ar/train.py edits, so they fit the loop, but run each with 3 seeds, because a single seed cannot tell a +1 sd effect from noise. Items 1, 2, 5, 6 and 7 touch the engine or the probe, so they need a re-setup, and the fast feedback is gone. I recommend batching them into one re-setup.

## Conclusion

Of the signals reviewed, the ones that change only the credit (a potential, a luck baseline, a better Q for the Trainer play itself) are consistent with row 60 and with self-discovery. The ones that would teach prompt answers directly all depend on a search-based oracle, which row 60 questions. The literature has no card-game precedent for any of these on tutor or setup cards, so every expected effect above is a hypothesis. A flat result on #1 would also move the question from signal toward architecture, which is the separate track.
