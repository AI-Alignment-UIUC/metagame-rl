# How LLM-driven research / program-search loops escape local minima of ideas

Scope: mechanisms from autoresearch-style agents and LLM evolutionary search, each with a "Loop change:" for metagame-rl's ar/ loop (agent edits only ar/train.py; fixed.py scores M; 21 rows, 0 kept; ideas.md missing). Tool budget ~13 calls; several papers were read only through abstracts, HTML excerpts or secondary coverage, flagged below. Dates: current as of Oct 2026.

Local-loop context (read from files): ar/program.md step 6 forces a "different part of train.py" only after 10 straight discards and STOP after 30; ar/results.tsv rows 5-21 show the agent did rotate axes (SD, LAM, ENT, END_W, curriculum, anchor, LR, probe k) but keep rule is a single-seed gain >= delta (0.0100) over best (0.4686) with a seed-2 confirm. A/A baseline spread is M 0.4665-0.4701 across seeds 1-3 (rows 2-4), but single-change rows move +-0.02 (e.g. LAM 0.8: 0.4815 then 0.4750; Frozen anchor 0.4917 then 0.4723; Curriculum 0.4829 then 0.4636), so seed-to-seed spread of one config is about 0.02, larger than delta.

## 1. Karpathy's autoresearch: design, reported failure modes, community fixes

### Takeaway
The upstream repo is deliberately bare (one editable file, 5-minute fixed budget, one metric, keep-if-better, ~12 experiments/hour); it documents no failure modes. Plateau, noise-chasing and greedy hill-climbing are reported only in third-party write-ups, with fixes being human nudges, a stale-idea backlog file, "plateau breaker" and confidence-margin add-ons. Treat all as anecdotal.

### Cited Findings
- Design: agent edits only train.py, fixed 5-minute wall-clock budget, metric val_bpb, keep or discard, ~12 experiments/hour and ~100 overnight; program.md is the human's main lever and is "intentionally kept as a bare bones baseline"; the page documents no keep threshold and no failure modes — [karpathy/autoresearch](https://github.com/karpathy/autoresearch)
- One author ran 165 experiments; gains flattened; the agent's own summary said the remaining gap needed something fundamentally new; asking it to research new ideas, or the human supplying ideas, restarted progress — [barazany.dev](https://barazany.dev/blog/what-karpathys-autoresearch-unlocked-for-me) (as summarized by search tool; single anecdote)
- Default program.md hill-climbs (keep only improvements); one author suggests accepting changes within ~1% of best to widen search; a third-party adaptation adds a "plateau breaker" that rewrites the approach after several stale runs and a "confidence margin" so small gains are not read as progress — [search summary of community write-ups](https://themenonlab.blog/blog/karpathy-autoresearch-autonomous-ml-experiments); these are community extensions, not in Karpathy's repo
- Warning that a too-short fixed budget gives "100 experiments that all show noise" — same summary (secondary)
- A community autoresearch skill keeps an `autoresearch.ideas.md` backlog: deferred promising ideas are appended; on resume the agent prunes stale entries and tries promising ones; after 3+ runs a confidence score reads >=2.0x as likely real, 1-2x marginal, <1.0x noise — [skillselion listing](https://skillselion.com/skills/paulrberg/agent-skills/autoresearch)
- I found no source describing automatic plateau detection in a maintained fork; the distributed fork autoresearch-at-home had no commits after 2026-03-13 as of June 2026 — [rywalker.com](https://rywalker.com/research/autoresearch-at-home)
- A Microsoft-attributed paper "Fork-and-Flush" (arXiv 2610.07447, posted Oct 2026) studies autoresearch agents directly: 8 repeats of the same agent on one task ended at 68.3 to 100.0, and extra compute did not close the gap ("idea basins"); history compression did not fix it — [explainx summary](https://explainx.ai/blog/fork-and-flush-idea-basins-autoresearch-agents-microsoft-2026)

### Inferences
- Our 21-row log has the signature the write-ups describe: one-change tweaks to a single recipe, ties within noise, and a keep rule that cannot distinguish +0.01 from seed noise. The A/A range (0.4665-0.4701) understates run noise for changed configs (see row pairs above), so "confirm" with 2 seeds is weak against ~0.02 spread; "kept" mostly selects lucky seeds, and "discard" can reject real gains.
- Loop change: (keep rule) Make the confirm step the real decision: keep only if the mean of 3 seeds beats the incumbent's 3-seed mean by delta, and re-estimate delta from the std of the seeds of one config (not from A/A of the unchanged recipe). Cost: +2 runs (10 min) only for candidates that pass seed 1, about 1 in 5; respects rules (evaluation-side only, game-agnostic, simple). Also have program.md forbid trend-reading from a single seed ("do not cite a single-seed delta as a trend").

### Gaps
- No primary-source (GitHub issue/discussion) evidence of failure modes; the search returned blogs only. Karpathy's repo issues were not fetched.

## 2. Context persistence and "idea basins": Fork-and-Flush, PACEvolve, AIRA-dojo

### Takeaway
The most direct evidence for a long-run agent getting trapped: it exploits its own earlier ideas because its context/memory rewards persistence. Fixes with measured effect are (a) discarding chat context while keeping workspace, (b) capped, de-duplicated idea memory with a permanent failed-idea log, (c) stagnation-triggered backtracking. ar/ already uses one fresh session per experiment (drive.py), so it has flush for free but pays for it with no memory of why things failed except results.tsv descriptions.

### Cited Findings
- Fork-and-Flush: fork K parallel branches from the workspace, wipe each branch's chat context, run a fixed horizon, continue from the best. Normalized score over 13 tasks: single run 0.47, best-of-4 0.54, Fork-and-Flush 0.78; flush alone (11 tasks) 0.45 to 0.55; normalized std 0.26 to 0.16; highest mean on 12 of 13 tasks. K and interval not stated; summary from abstract plus press, no public code — [explainx](https://explainx.ai/blog/fork-and-flush-idea-basins-autoresearch-agents-microsoft-2026); press coverage figures differ slightly (0.71 vs 0.57/0.55/0.45 on an 11-task ablation) — [neoteo](https://www.neoteo.com/en/fork-and-flush-topped-an-11-task-test-of-ai-agent-context-clearing)
- PACEvolve: append-only idea memory fails to escape local minima; "LLMs exhibit a strong bias towards exploiting selected ideas, persisting with them even when only minor or negligible improvement is observed." Fix = Hierarchical Context Management (persistent pool of conceptual ideas; an LLM classifier checks if a proposal matches an existing idea or is new; cap hypotheses per idea, summarize at cap; cap total ideas, drop least promising; permanent log of failed ideas), Momentum-Based Backtracking (EWMA of fraction of remaining gap closed; below threshold the agent reverts to an earlier state sampled by a power law favoring early iterations and resets context), and Collaborative Evolution across islands (backtrack vs crossover). Ablation is qualitative: HCM raised mean/best but left worst runs poor; adding MBB removed the worst runs but slightly lowered the best; adaptive cross-island sampling restored the best — [PACEvolve arXiv 2601.10657](https://arxiv.org/html/2601.10657). Thresholds are in an appendix I did not read. Result on Modded NanoGPT was small (142.8s to 140.2s).
- AIRA-dojo (Meta FAIR, MLE-bench Lite): with AIDE's operators, MCTS/evolutionary offered no benefit over greedy (all ~35-39%); with improved operators greedy 45.5% (vs AIDE greedy 39.8%) and MCTS ~47-47.7%; "the operator set can act as a bottleneck". Operator changes: draft/improve see only sibling memories (to promote diversity), debug sees the full ancestral chain (to avoid undo-redo loops), complexity cue depends on child count, think tokens. Removing AIDE's memory left medal rates nearly unchanged. Test-vs-validation selection gap of 9-13 medal-rate points — [Toledo et al., arXiv 2507.02554](https://arxiv.org/html/2507.02554v2)
- A search summary attributed to the same line of work says low-ideation-diversity agents (AIRA_GREEDY) dropped valid-submission rate 98% to 92% by repeating one problematic approach — reported by a search-tool summary of a snippet; the fetched AIRA-dojo page (first 100k chars of 125k) did not contain it. Unverified.

### Inferences
- The AIRA result ("search policy matters only when operators are good") suggests that for us the lever is what the proposer sees and is asked to do, not a fancier loop around the same proposer. Sibling-only memory for improving and ancestral memory for debugging maps to: "when proposing a new idea, see only the one-line category list and failed-idea ledger; when fixing a crash, see the full diff history".
- Loop change: (program.md + ideas.md) Add a `## Ledger` at top of ar/ideas.md: one line per *idea family* (not per experiment) with `family | tried N times | best M | verdict (dead / alive / untested)`; instruct "propose only from alive/untested families; a family becomes dead after 2 tries with no gain >= noise". Cap the ledger at ~12 families and summarize old rows, as PACEvolve caps ideas. Cost: zero compute, ~15 lines of prompt; respects rules (agent still edits only train.py). Already half-present: results.tsv descriptions are long and repeated per row (rows 10-12, 16-17, 18-19 repeat an entire description twice), so a family ledger would shrink context rather than add.
- Loop change: (stagnation) Replace "10 discards then touch a different part of train.py" (which the agent already satisfies by rotating knobs — Audit A1 shows rotation among same-recipe knobs) with a structural trigger: after 6 discards in a row, the next experiment must change the *model, the practice decks, or the observation/action interface* (MODEL_OVERRIDES, practice_matchups use, new input), not a loss or schedule constant. Cost: none; compatible with scope in program.md ("Scope" line lists MODEL_OVERRIDES and practice).

### Gaps
- Exact PACEvolve thresholds, Fork-and-Flush K/interval and task list not read. Fork-and-Flush's full paper not read; figures come from an aggregator and press.

## 3. FunSearch, AlphaEvolve, ShinkaEvolve, OpenELM, MAP-Elites: population structure, resets, novelty filters

### Takeaway
Evolutionary program-search systems keep diversity structurally (islands with periodic resets of weak islands, MAP-Elites grids, novelty rejection before evaluation). Evidence that these raise *best* score (not just spread) is strongest for ShinkaEvolve's novelty rejection (one ablation on circle packing) and weak elsewhere; bandits over LLMs give only modest gains. Most of these assume hundreds to thousands of cheap evaluations; at 5 minutes per evaluation and ~12/hour, population machinery is mostly unaffordable, but its cheap parts (novelty check before running, family archive) transfer.

### Cited Findings
- FunSearch (per LLM4AD docs): programs are grouped into clusters by score within islands; softmax sampling with decreasing temperature (explore to exploit); periodic reset of underperforming islands by copying best programs from successful islands. A "worst half" rule or signature-keyed clustering was not found in the secondary source — [LLM4AD FunSearch doc](https://llm4ad-doc.readthedocs.io/en/latest/method/funsearch.html)
- AlphaEvolve ablations (tensor decomposition and kissing number) report big drops without iterative evolution and when problem-specific context is removed from prompts; no meta-prompt ablation details found — [Composio summary](https://composio.dev/blog/alphaevolve-evolutionary-agent-from-deepmind) and [E. Davis notes](https://cs.nyu.edu/~davise/papers/AlphaEvolveNotes.pdf) (secondary). I did not read the primary AlphaEvolve paper.
- ShinkaEvolve (ICLR 2026): islands; parent sampling weighting fitness and novelty (power-law or performance+offspring-count weights); novelty rejection sampling before evaluation (embed mutable code, cosine similarity against archive; above ~0.95 an LLM judge decides if the change is meaningful); UCB1 bandit over which LLM mutates. Circle-packing ablation: embedding-plus-LLM-judge rejection "strongly outperforms" no rejection; bandit LLM ensemble "slightly improves" over uniform — [ShinkaEvolve arXiv 2509.19349](https://arxiv.org/pdf/2509.19349) via search snippets; threshold value and bandit reward detail not verified against the paper.
- OpenELM supports MAP-Elites, CVT-MAP-Elites, Deep Grid MAP-Elites with LLM mutation/crossover; I found no ablation from OpenELM itself — [CarperAI/OpenELM](https://github.com/CarperAI/OpenELM)
- LEVI (arXiv 2605.09764) diversity ablation on scheduling: unseeded archive widest but low-scoring; weaker behavior dimensions concentrate 35% of elites in one algorithm family; the full method keeps elites across 4 of 5 families — [LEVI](https://arxiv.org/pdf/2605.09764) (snippet only; scheduling domain)

### Inferences
- Embedding similarity on code diffs is a poor novelty signal for us: all 17 tweaks are small train.py diffs that embed close together, yet were judged "different" by the agent. ShinkaEvolve's insight transfers as a *pre-run gate*, not as embeddings: before running, the agent writes the idea's family and must state which row numbers it differs from structurally.
- Loop change: (novelty gate, program.md) Add to step 2: "Name the family (loss weight / schedule / data-practice / opponents / model / interface / search-target). If the family already has >= 2 rows in results.tsv, you may only continue it if you cite a probe finding in ideas.md that predicts a different outcome." Cost: zero compute; replaces the current prose "say how it differs from earlier rows" (which agent satisfies verbosely, rows 6-22). Respects rules.
- Loop change: (cheap bandit, planning session) Instead of a UCB bandit over LLMs, run a count-based rotation over *families*: the driver (drive.py, not the agent) prints the family with fewest tries and lowest-tried-per-gain into the prompt as "suggested family this round". Cost: ~20 lines in drive.py, no GPU; respects rules but touches the harness, so needs Evan's okay; agent still free to override with a stated reason.

### Gaps
- No ablation I could verify that shows island resets or MAP-Elites raise best-found score for LLM program search; FunSearch/AlphaEvolve primary papers unread. No clean study of cost-effectiveness at <20 evaluations/day scale.

## 4. AIDE / MLE-bench / AI Scientist: tree search, debug vs improve, idea diversity

### Takeaway
Tree-search agents (AIDE greedy; AI Scientist-v2 best-first tree search with an experiment-manager agent) separate "debug" from "improve" and keep several branches alive. Evidence says the search policy adds little unless proposal operators are good (AIRA-dojo), and that v2's broader exploration lowers success rate. Diversity gains are real but small compared to operator quality.

### Cited Findings
- AIDE: tree search over candidate solutions; search policy is hard-coded (error code => debug; else improve; or draft new root); 16.9% medal rate on MLE-bench with o1-preview, ~4x the next agent in the original comparison — [AIDE arXiv 2502.13138](https://arxiv.org/pdf/2502.13138)
- AIRA-dojo numbers and scoped-memory operators: see section 2 — [arXiv 2507.02554](https://arxiv.org/html/2507.02554v2)
- AI Scientist-v2: removes v1's human code templates; an experiment-manager agent decides which node to expand, debug, or abandon in a best-first tree search; one of three autonomous workshop submissions scored above the average human acceptance threshold (summary reports 6.33/10, later withdrawn); the repo says v2 is more exploratory with lower success rates than v1; critical commentary reports hallucinated or faked results and overestimated novelty — [AI Scientist-v2 arXiv 2504.08066](https://arxiv.org/pdf/2504.08066), [repo](https://github.com/sakanaai/ai-scientist-v2), [summary](https://blog.pebblous.ai/project/AgenticAI/ai-scientist-v2/en/) (stage list "feasibility, hyperparameter tuning, core agenda, ablation" unconfirmed against paper)
- Validation-guided search overfits: choosing the final node by test instead of validation score would add 9-13 medal-rate points; submitting top-3 validation nodes recovers ~10% — [arXiv 2507.02554](https://arxiv.org/html/2507.02554v2)

### Inferences
- The generalization gap is our single-seed problem in another form: selecting on a noisy score picks lucky nodes. The remedy that transfers is the multi-seed keep rule (section 1) and keeping *several* near-ties rather than one incumbent.
- Debug vs improve: ar/program.md already allows one typo-level fix per crash; row 16 crashed and was rerun as rows 17-18 with the whole description duplicated; fine. Not a bottleneck.
- Loop change: (keep rule, minimal tree) Do not keep near-ties as extra branches (adds state to a loop that resets via git); keep a tag only for rows that pass confirm. Cost low; marginal value; optional.

### Gaps
- Did not verify the AI Scientist-v2 stage structure or its idea-diversity analyses; MLE-bench paper not read directly. No analysis of mode collapse in AIDE's proposals found.

## 5. Idea-level novelty, quality-diversity over ideas, and whether it improves kept results

### Takeaway
Two 2026 sources link *variable-level* novelty (what is being changed, not paraphrase) with performance in autoresearch, and a quality-diversity ideator multiplies the number of distinct, high-quality ideas. Neither measures kept improvements in a long loop with noisy single-seed scores, so "diversity raises kept gains" is supported only for task-score outcomes (Fork-and-Flush, PACEvolve, AIRA), not shown for ideation modules alone.

### Cited Findings
- "Measuring the Creativity of Frontier LLMs in Automated Research" (arXiv 2609.14057): on Karpathy's autoresearch task, models were similar in value and exact-match novelty but differed substantially in *variable-level P-Novelty* (whether the modified variable/combination was explored before), which had a strong positive correlation with research performance. The arXiv page says the authors withdrew it in v3 and shows the abstract only — [arXiv 2609.14057](https://arxiv.org/abs/2609.14057). Treat as weak evidence.
- IDEAgent (arXiv 2607.22375): treats ideation as quality-diversity search; Ideator/Stenographer/Quality Evaluator/Soundness Panel/Diversity Judge; diversity judged against accepted, superseded and rejected-pattern memories; eight semantic descriptor axes (failure mode, causal diagnosis, intervention...); at NB>=7, 3.89x the Yield of the best baseline and 27/32 topics with a qualifying idea vs 8/32; scaling the stateless baseline 5x did not close the gap. LLM-judged; external judge agreement for soundness weighted kappa ~0.26; no test of whether ideas work — [IDEAgent](https://huggingface.co/papers/2607.22375.md)
- PACEvolve's classifier "same idea vs new idea" and failed-idea log are the closest to an idea archive that ran inside a performance loop, with gains largest on worst-case runs — [arXiv 2601.10657](https://arxiv.org/html/2601.10657)
- A community search-agent playbook says to break plateaus with explorer agents, give a summary of already explored ideas as context, and avoid telling agents which specific ideas to pursue — [search summary, skillsmp swarmresearch](https://skillsmp.com/creators/swarmresearch/swarmresearch/claude-skills-swarmresearch) (low-quality secondary source)

### Inferences
- "Variable-level novelty" fits Audit A1 exactly: the agent changed new *constants* (SD, LAM, ENT) each time but always the same variable class (loss/schedule scalars). A descriptor that is a short list of *what part of the pipeline* changed is cheaper than 8 semantic axes and sufficient at N=20.
- Loop change: (ideas.md structure, MAP-Elites-lite) In ideas.md keep a 2-axis table: rows = *where the change acts* {policy input/encoder, model architecture, practice decks, opponents, search targets, reward/credit, optimizer}, columns = *hypothesis about why Trainers are undervalued* {credit horizon, exploration noise, data distribution, representation, search coverage}. Each results.tsv row must name its cell; the agent picks from empty cells first. Cost: zero compute; ~20 lines; respects rules (cells describe train.py regions, no card names). Rows so far fall into ~4 of 35 cells (credit/loss, data/practice, opponents, search coverage), which makes the gap visible.
- Loop change: (separate critic, optional) Before running, a 2nd short `claude -p` call (critic) sees the proposed commit message plus the ledger and replies accept / reject-as-duplicate / reject-as-noise-chasing. Evidence for proposer/critic splits improving kept results was not found in this research (IDEAgent's judges raise idea quality scores, not outcomes). Cost: one extra short session per experiment, no GPU; mark as a trial to A/B over 10 rows, not a default.

### Gaps
- No study found showing a novelty archive or critic raises the number of *kept* improvements in an autoresearch loop; evidence is task-score level or LLM-judged idea quality. "Explain the last N failures before proposing" had no dedicated study found; PACEvolve's failed-idea log and AIRA's ancestral debug memory are adjacent evidence only. Bandit-over-idea-category evidence: only ShinkaEvolve's bandit over LLMs (modest).

## 6. Feeding external diagnostics and probe findings to the agent (the ideas.md channel)

### Takeaway
I found no paper that studies diagnostic-first steering of an autoresearch loop. The adjacent evidence says: problem-specific context matters a lot (AlphaEvolve ablation: dropping it hurt), human-supplied ideas restart plateaued agents (single anecdote), and agents persist with their own ideas unless memory is restructured. So the channel should deliver short, falsifiable claims with explicit "what this predicts about train.py", and the agent should be required to act on or rebut each.

### Cited Findings
- Removing problem-specific context from AlphaEvolve prompts reduced effectiveness — [Composio summary](https://composio.dev/blog/alphaevolve-evolutionary-agent-from-deepmind) (secondary)
- Human ideas or asking the agent to research new ideas restarted a plateaued autoresearch run — [barazany.dev](https://barazany.dev/blog/what-karpathys-autoresearch-unlocked-for-me) (anecdote)
- The community `ideas.md` backlog pattern: append deferred promising ideas, prune stale ones on resume, try promising ones — [skillselion](https://skillselion.com/skills/paulrberg/agent-skills/autoresearch)
- program.md in ar/ already says take ideas.md ideas first and name them in the commit message (local file, ar/program.md line 37-39); the file does not exist, and the probe finding that Trainer-prompt choices are no better than random (Audit A1 brief) has not been delivered.

### Inferences
- A finding that says "Trainer prompt choices are random-quality" is a diagnosis, not an idea; delivered raw the agent can ignore it (it already tried ENT 0 for a related reason, row 8). Phrase each as: Finding (n, date, probe id) / Implication for train.py (a testable change class) / Status (untested, tried in row k, refuted).
- Loop change: (ideas.md format) Create ar/ideas.md with sections: `## Ledger` (families, section 2), `## Probe findings` (3-line entries as above, newest first, max 8, retire when tried), `## Evan's ideas` (verbatim, tried / not tried per the standing preference), `## Empty cells` (the table in section 5). Rule in program.md: "the first experiment of each session must test the top untested item in Probe findings or Evan's ideas; if none, take an empty cell." Cost: zero compute; the planning session writes the file after each probe (one append per probe). Respects rules: self-discovery holds as long as findings describe the pilot's behavior from evaluation probes, and train.py still sees no human lists, card kinds or names (fixed.py rejects it); phrase findings generically ("choices inside prompts that offer many options").
- Loop change: (plan.json fill) Have the planning session choose each probe as the cheapest test that *separates two row-level hypotheses* from results.tsv (e.g. "search covers Trainer plays at rank >= 5" vs "PPO erodes them"), and write the predicted effect on M for each family in ideas.md before the probe runs. After a probe, write the verdict (supports / refutes) into the ledger so a family can be killed on a probe instead of 2 GPU-expensive rows. Cost: no extra GPU beyond planned windows, which borrow time from ar/ (each window costs about 1-2 experiments). Respects rules.
- Loop change: (budget split, explicit) Reserve every 4th ar/ session for a "structural" experiment (model override, observation change, different practice-deck distribution) and allow it a longer budget by changing fixed.py only via a new --setup/--calibrate that Evan approves; not allowed to the agent. Cost: new calibration (CLAUDE.md says a change to fixed.py needs --setup and --calibrate); only worth it if the 5-minute budget is judged too short for structural changes (not shown here).

### Gaps
- No quantitative evidence for how probe-to-agent feedback changes kept-improvement rate; this is untested in the literature I could reach. No source on how long/structured an ideas file should be.

## Summary of ranked loop changes (cost, rule check)
1. Multi-seed keep rule with delta from config-level seed std (+2 runs for ~1 in 5 candidates; respects rules). Highest evidence need: A/A std understates noise by ~2x in our own rows.
2. Family ledger plus novelty gate in program.md/ideas.md (zero compute; shrinks context; respects rules). Backed by PACEvolve (capped idea pool, failed-idea log) and variable-level novelty correlation (weak, withdrawn paper).
3. Structural trigger after 6 discards (model / practice decks / interface, not scalars) (zero cost). Backed by AIRA (operators over policy) and the plateau anecdotes.
4. ideas.md with Probe findings + Evan's ideas + empty-cell table; planning session writes each probe's verdict and the predicted M effect (zero GPU). Evidence indirect.
5. Optional: critic pre-check session; driver-suggested family rotation (needs Evan's okay, low evidence).
6. Not recommended: islands, embeddings, MAP-Elites grids over code, parallel fork-and-flush (needs K x GPU and 5-minute runs share one GPU; ar/ already flushes context per session).
